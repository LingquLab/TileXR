# Combine V2 Group 优化备忘录 0817

## 范围与前提

本备忘录来自对 128P `MoonEpCombineV2Group` 路径的静态性能审查。调用方保证输入可靠，多轮调用串行，UDMA QP 可在轮次间复用但不存在并行执行。以下项目尚未进行实机性能验证，实施时需逐项测量。

## 优先级建议

### P0：删除热路径中的冗余同步

当前一轮有 13 次 `SyncAll<true>()`：入口 1 次，4 个 collective stage 每个包含 Begin 1 次和 End 2 次。在可信输入的 fast path 中：

- `reduceHidden=false` 时可以不做跨核同步。
- `reduceHidden=true` 时只保留 Reduce 前 1 次跨核同步，保证所有接收写入对 Reduce 可见。
- 删除同步时应同步删除仅为 stage failure convergence 服务的状态读写。

### P0：合并 CLOS 的两次目标扫描

每个 CLOS step 先通过 `CountPeerRows()` 扫描一次 `dstLocal`，实际构建 WQE 时又扫描一次。`nvS=131072` 时每次扫描为 512 KiB；按当前平衡 128P 映射估算，每 rank 约有 248 次完整扫描，合计约 124 MiB GM 读取。

建议在单次构建中保留每个 lane 的最后一个 WQE，扫描结束后直接为其设置 completion flag，从而删除 `CountPeerRows()` 预扫描。需确保空 lane、batch 边界和 outstanding 上限的处理不变。

### P1：删除或避免 Stage 大块 D2D Copy

按当前 128P 配置，hidden input 拷贝约 896 MiB，reduced output 拷贝约 56 MiB。

- Reduce 可直接将结果写入 `hiddenSh`，删除 reduced output 的二次拷贝。
- 若上游能够直接将 hidden input 产出到 registered workspace，可删除输入 D2D Copy。这是接口和内存布局协同优化，不应在 kernel 内假设别名关系。

### P1：缓存 Host 启动不变信息

Host 每轮重复校验 device core count、QP count、Fullmesh view 和 128 个 registry region，Stage 与 Run 中还会重复计算 workspace layout。建议在 plan/workspace/QP 世代变化时做一次完整校验，缓存 fast launch context；每轮只校验会变化的指针、shape 和运行参数。

### P2：减少控制面 GM 访问和指令

- CQ poll 先只读 owner，owner 就绪后再读 status、substatus 和 entry index。
- Done 复用 CLOS data descriptor 的不变部分，只改写控制 WQE 字段。
- Credit 可评估简化为 64-bit magic/step token，但需先证明 target core 和 epoch 可由唯一 slot 隐含。
- timeout cycle 可每 N 次 poll 采样，保留有界超时语义。
- 只有执行 Self route 的 core 需要 Self relay UB；当前每个 core 都分配 128 KiB，可评估分时复用或按 route 裁剪。

## 不可因 fast path 删除的约束

- 每轮必须从复用 QP 的真实 SQ/CQ head/tail 状态继续，不能假设从零开始。
- CQ owner/status/substatus 校验不能删除；只能调整读取时机。
- WQE 的 MTE3 发布完成必须先于 `st_dev` doorbell。
- payload CQ 成功后才能发 Done。
- Done/Credit 仍需 magic/epoch/step 防止轮次复用误匹配，相关 DCCI 不能无证据删除。
- `reduceHidden=true` 时，Reduce 前必须保留一次跨核可见性同步。

## Profiling 审查

Profiling 的编译开关、构建脚本参数、workspace record 布局、kernel 写回和 hardware probe 读取链路均已存在。当前记录 ABI 为 version 5，单条 record 为 448 Byte。

128P Group 路径曾漏记 `MOONEP_COMBINE_V2_DIAG_FULLMESH_CQ_SUCCESS`，使 hardware probe 要求的 `WQE_BUILD_END < SUBMIT_END < CQ_SUCCESS` 时间序不成立。修复点应位于最终 Fullmesh CQ 等待成功后，不记录批次中途用于 outstanding 流控的 CQ，以保持指标语义。
